# ODMFlow Web

ODMFlow 的独立对话前端。以浅色聊天工作区承载产品咨询、需求评估、订单查询与售后申请，让用户在同一私人会话中完成咨询、查看执行依据并确认业务操作。

前端只负责交互、展示和调用后端协议，不直接访问数据库、模型服务或向量库，也不在浏览器中决定业务权限。

## 核心能力

- **身份入口**：可切换的注册与登录界面、刷新恢复身份、退出登录及用户切换。
- **私人对话**：单一会话列表、历史消息、发送后立即展示用户消息、逐字流式回复与完成状态。
- **执行可视化**：按实际执行展示任务、工具与 RAG 记录，可展开查看候选片段、排名、距离、注入证据与耗时。
- **业务确认卡**：绑定发起申请的原始轮次，支持确认、取消和查询结果；后续聊天不会把卡片移到末尾。
- **用户画像**：查看、修改和删除个人偏好，配合后端版本校验处理冲突。

## 快速启动

以下命令在**前端根目录（包含 `package.json`）**执行，示例使用 PowerShell；Linux/macOS 复制模板时可使用 `cp`。

### 1. 环境与配置

需要 Node.js 22.12+ 与 npm，并已按后端 README 完成数据库初始化和服务启动。前端不需要 MySQL 连接或模型 API Key。

```powershell
npm ci
if (-not (Test-Path .env.local)) { Copy-Item .env.example .env.local }
```

`.env.local` 中的两个配置分别是：

```dotenv
VITE_API_BASE_PATH=/api
DEV_API_TARGET=http://127.0.0.1:8000
```

`VITE_API_BASE_PATH` 是浏览器可见的同源 API 前缀；`DEV_API_TARGET` 只供开发代理使用，必须是无凭证、无附加路径的后端 origin。不要在任何 `VITE_` 变量中填写密钥。

后端实际 `.env` 的 `ODMFLOW_APP_ORIGIN` 应为 `http://127.0.0.1:5173`。浏览器统一使用 127.0.0.1，避免与 localhost 混用。

### 2. 启动与验证

```powershell
npm run dev
```

访问 [http://127.0.0.1:5173](http://127.0.0.1:5173)，首次注册后登录。前端与后端各保留一个运行终端；前端启动不会替你启动后端。配置修改后重启 Vite。

验证登录、发送消息和刷新后的历史恢复；要验证知识引用，需在后端另行完成 RAG 初始化。未登录时身份接口 401 是正常状态，502 则通常表示代理无法连接后端。

## 构建与部署

```powershell
npm run build
```

产物为 `dist/`。可使用 `npm run preview` 在本机检查构建结果，但它不是生产服务器，也不能代替生产 API 网关。

正式部署时：

1. 将 `dist/` 部署到静态服务器，提供 SPA 路径回退到 `index.html`。
2. 在同一 HTTPS origin 配置 `/api/` 代理到后端，移除 `/api` 前缀并保留查询参数、Cookie 与 Origin；不要把生产来源伪装成回环地址。
3. 代理支持 POST SSE，关闭响应缓冲并设置足够读取超时；仅代理普通 JSON 请求会导致流式体验异常。
4. 后端设置生产模式与该 HTTPS origin，保持详细调试关闭。身份、权限与 CSRF 校验不可在代理层绕过。
5. `VITE_API_BASE_PATH` 若更改，重新构建并同步网关路径。`DEV_API_TARGET` 不会成为生产代理配置。

实际 `.env.local`、`node_modules/` 和 `dist/` 不提交；依赖声明、锁文件及无密钥模板保留。

## 技术架构

React、TypeScript、Vite 与 TanStack Query。身份等服务端查询使用 TanStack Query；会话选择、输入、流式消息及确认卡交互使用 React 状态，不把所有状态强行放入同一容器。

| 模块                                                                        | 职责                                           |
| --------------------------------------------------------------------------- | ---------------------------------------------- |
| [src/main.tsx](src/main.tsx) / [src/app](src/app/)                          | 应用挂载、查询上下文、身份分支与工作区组合     |
| [features/auth](src/features/auth/)                                         | 注册登录、身份恢复、退出与身份查询             |
| [features/conversations](src/features/conversations/)                       | 会话列表、消息历史、流式事件处理与执行详情面板 |
| [features/actions](src/features/actions/)                                   | 订单及售后确认卡、确认/取消请求与结果状态      |
| [features/profiles](src/features/profiles/)                                 | 用户偏好画像的展示与管理                       |
| [shared/api](src/shared/api/)                                               | 统一请求封装、凭据携带及错误处理               |
| [shared/config](src/shared/config/)                                         | 浏览器公开配置与 API 路径规则                  |
| [styles](src/styles/)                                                       | 设计变量、浅色主题与全局样式                   |
| [config/devProxy.ts](config/devProxy.ts) / [vite.config.ts](vite.config.ts) | 开发代理、路径重写与开发服务器配置             |

## 页面与数据流

```text
进入页面 → 查询当前身份
  ├─ 未登录 → 登录 / 注册 → 对话工作区
  └─ 已登录 → 恢复工作区 → 读取本人会话与历史

发送消息 → 立即展示用户消息 → POST 流式请求
  → accepted 确认受理 → 增量回复与执行事件
  → completed 确认最终状态 → 刷新持久化结果

申请确认卡 → 用户确认 / 取消 → 后端恢复确认流程
  → 更新原轮次卡片与业务结果
```

消息流使用 `fetch` 发起 POST，并消费 SSE 事件，不使用 WebSocket。刷新后以后端持久化数据恢复页面；连接中断或结果不确定时查询已有状态，不自动重放业务写操作。

身份以服务端 Session 为准。未登录的 401 与网络错误分别展示，切换用户时清理原身份下的缓存与页面状态，不在浏览器存储模型密钥或登录凭据。

## 接口与配置边界

所有后端请求使用统一 API 前缀。开发环境默认通过同源 `/api` 代理到后端，并移除该前缀；后端实际路由不带 `/api`。

| 后端接口              | 前端用途                               |
| --------------------- | -------------------------------------- |
| `/auth/*`             | 注册、登录、身份恢复、退出及 CSRF 信息 |
| `/conversations/*`    | 会话列表与历史消息                     |
| `/agent/turns/stream` | 发送消息并接收流式回复、执行事件       |
| `/agent/actions/*`    | 确认卡查询、确认与取消                 |
| `/memory/profile`     | 本人用户画像管理                       |

[.env.example](.env.example) 只提供前端必要配置模板：`VITE_API_BASE_PATH` 是构建时注入的公开路径，`DEV_API_TARGET` 仅用于 Vite 开发代理。实际 `.env.local` 不进入版本管理，浏览器可见配置不得包含秘密。

生产环境需要同源反向代理承接 Cookie、CSRF 与 SSE，Vite 开发代理不是生产网关。执行详情是否可见由后端配置决定；前端展示可观测事件和资料来源，不展示模型内部思维链。订单、售后及交易边界以服务端规则为准。

## 常见问题

| 现象                     | 优先检查                                                            |
| ------------------------ | ------------------------------------------------------------------- |
| `/api/auth/me` 返回 502  | 后端是否运行、开发目标地址、端口与代理配置                          |
| `/auth/me` 返回 401      | 未登录时属于正常身份恢复流程                                        |
| 登录被拒绝               | 后端 Origin 是否等于浏览器来源；核查 CSRF 与 Cookie，不绕过安全校验 |
| 消息不逐字显示           | 模型是否支持流式输出、网关是否缓冲 SSE、读取超时是否足够            |
| 构建后 API 不通          | 是否配置生产同源网关；Vite 开发代理不会跟随 `dist` 发布             |
| 资料来源或执行详情未显示 | 是否实际执行检索/工具，以及后端调试配置；前端不能强制开启详细记录   |
