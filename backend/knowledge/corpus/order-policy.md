# ODMFlow 合成售前与模拟订单政策

> 以下仅解释模拟流程，**不是现实商业条款**；不涉及真实交易。

## 售前路径

1. 用户可先咨询产品线、可讨论定制项和需要准备的资料，普通咨询不代表已创建订单或提交申请。
2. 对非目录内配置，Agent 收集用途、销售国家、产品形态、连接方式、数量、必选/可选功能、GMS/MDM 需求与交付意向；答复为“待技术/商务评估”，不能自动报价或承诺可行。
3. 用户**明确要求提交**时，应先核对选择与未知项，确认其为**模拟订单申请**；是否受理以办理结果为准，暂不可在线办理时可先整理材料。申请不等于正式合同、付款、认证通过或量产排期。

## 模拟订单申请的边界

- 只允许已登录用户为自己发起；不能冒用其他人的身份或查询其他客户的记录。
- 至少需要产品线/型号、数量、目标销售国家、连接方式和配置摘要；信息不充分时先澄清。
- 办理前必须向用户展示摘要与“模拟、待审核”的性质，取得明确确认；仅有对话中的意向不代表已提交。
- 如用户要求真实价格、MOQ、交期或具体证书编号，资料包均不提供；Agent 应明确转为人工商务/合规核查。
- 已提交订单的进度以本人可访问的订单记录为准，不能从政策介绍或以往谈话推测当前状态。
- 取消/修改请求是不同的高影响动作，需单独的权限、状态、确认和审核规则；本文不授权 Agent 直接执行。

## 模拟服务流程

`咨询 → 方案评估 → 样机/确认 → 模拟订单申请 → 审核 → 模拟履约 → 交付 → 售后`

具体申请可能跳过或重复某些步骤；流程介绍不等于报价、物流安排或办理结果。
