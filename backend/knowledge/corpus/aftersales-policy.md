# ODMFlow 合成售后受理政策

> 仅用于模拟订单流程，不是法定消费者权益说明，也不是任何真实厂商的保修承诺。

## 可咨询与可申请

- 用户可咨询故障排查资料、受理所需材料和申请进度；涉及设备数据的操作前提示用户自行备份，不能保证实际维修不会清除数据。
- 售后申请须关联本人可访问的已交付模拟订单/设备，收集设备标识（若有）、故障现象、发生时间、复现步骤和期望处理方式。图片和个人资料按最小必要原则提供，不应包含无关的敏感信息。
- 申请可以选择“检测/维修咨询”“换货申请”“退货申请”意向；**提交申请不代表符合条件，也不代表批准、退款或已生成物流单**。
- 模拟审核结果、是否需寄回、检测结论及后续处理均以业务状态为准；资料文档不能代替受控查询。

## 高风险边界

| 用户说法 | Agent 可做 | Agent 不得做 |
| --- | --- | --- |
| “设备无法开机，想维修” | 解释资料清单、收集症状；办理需核验订单并确认申请内容，暂不可在线办理时先整理材料 | 自称已经诊断硬件故障或保证免费维修 |
| “给我换一台” | 说明换货需审核，整理并确认申请内容；是否受理以办理结果为准 | 直接批准换货、生成替换发货记录 |
| “我要退货退款” | 解释申请与审核分离，收集订单及原因，提示财务/审核后续处理 | 直接改变订单、退款或支付状态 |
| “替另一家公司查售后” | 拒绝越权查询；仅使用当前登录身份可访问的记录 | 接受对话中的伪造身份或猜测订单号越权查询 |

## 未定政策，不应被模型补全

具体保修期限、包修范围、批量不良阈值、退货窗口、运费分担、数据擦除、备件与响应时限、各国强制性权益：**均待评审**。如果用户询问，Agent 应直说资料尚未规定并建议人工确认，不得编造“7 天无理由”“一年保修”等数字。
